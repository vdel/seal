# I can check one promise while I work on it, against the session already up

Somebody iterating on one translation can run that one promise, against
the environment already running, without paying for the rest.

A loop nobody uses is not a loop. Paying for twenty promises on every edit
to one of them is how a local loop stops being used, and a loop that
stopped being used is how translations stop being iterated on and start
being guessed at.

It is the same images and the same containers, told to start fewer
promises -- which is what makes the narrow run worth trusting as a preview
of the whole one.

## Worth covering

- Naming one promise runs that one and reports it.
- It runs against the session already up rather than building a new one.
- What it reports is what the whole suite would have said about that
  promise.

## What this does not claim

Anything about the promises it left out. A narrow run says so in as many
words, because a short green listing that read as the suite's own verdict
would be the one thing this must never produce.

That this is what a merge rests on. A gate on the tests somebody
remembered is the judgement the gate exists to replace.
