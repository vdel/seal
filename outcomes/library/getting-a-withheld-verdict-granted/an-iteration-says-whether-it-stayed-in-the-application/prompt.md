# an iteration says whether it stayed inside the application

After a round of work on a red suite, whether it reached for the
specification is a fact somebody can check -- not something the party that
did the work reports about itself.

The whole gate rests on the difference between fixing the application and
changing what was promised. Asking the agent which it did puts the
question to the party with an interest in the answer, at the moment it is
least convenient to answer honestly.

So it is established rather than asserted. Reviewing a round then starts
from a fact instead of a claim, and the reviewer's attention goes to the
rounds that need it.

## Worth covering

- A round that changed only the application says so.
- A round that touched the specification says so, and names what.
- The answer comes from what changed, not from what anybody said about it.

## What this does not claim

That touching the specification is wrong. Sometimes a promise really is
stale -- what is promised is that it is visible, not that it is forbidden.

That an application change is a good one.
